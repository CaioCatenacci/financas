# Calendário das rotinas do mês

> Origem: conversa de 09/10/2026 ("calendário como o do LM Ateliê, para eu não esquecer de mandar os dados") e de 14/10/2026 ("vamos atacar o item do calendário"). Referência: B29 do LM Ateliê (grade rotina × semana, estilo gráfico de contribuições do GitHub, no hub).

## Problema

O fechamento hoje olha só os imports (Itaú, C6, fatura) e o salário: está no bloco do topo do Resumo e na grade "ver 12 meses" (G2), e o Telegram lembra nos dias 5 e 15 (G5). As outras rotinas do mês (prints do patrimônio, triagem do que ficou sem categoria, diagnóstico) não aparecem em lugar nenhum como "feito/falta", e a grade fica escondida atrás de um link.

## Valor

Uma olhada responde "o que falta fazer neste mês" para todas as rotinas, e o histórico mostra quais meses ficaram para trás.

## Pronto quando (DoD)

- [ ] o bloco do fechamento no topo do Resumo vira uma grade **sempre aberta**: linhas = rotinas, colunas = os 12 meses terminando no mês selecionado (o link "ver 12 meses" e o "esconder" saem)
- [ ] linhas, **uma por item**: Itaú extrato · Itaú fatura · C6 extrato · Salário (Wise) · um print do patrimônio por conta que já apareceu em `patrimonio` (hoje: Itaú/Caio, C6/Paola, Nubank/Paola, Mercado Pago/Paola, FGTS/Caio) · Triagem (sem categoria) · Diagnóstico
- [ ] cada célula tem um de quatro estados, com cor própria e um texto curto no `title`: **feito**, **parcial**, **falta**, **não se aplica** (cinza)
  - extratos: feito/parcial/falta = a cobertura do G2 (`cheia`/`parcial`/`faltando`); o mês corrente nunca passa de parcial
  - fatura: feito se existe a do mês, senão falta
  - salário: feito se há conversão real no mês, parcial se o mês está estimado, falta se não há nem estimativa
  - print do patrimônio: feito se a conta tem foto naquele mês (`total_cents` não nulo), senão falta; meses antes do primeiro print de qualquer conta = não se aplica
  - triagem: feito com 0 sem categoria, parcial com 1 ou mais (o número aparece na célula); mês sem nenhuma transação = não se aplica
  - diagnóstico: feito se há diagnóstico salvo do mês; falta se o mês está fechado e não há; mês ainda não fechado = não se aplica
- [ ] o estado do mês (faltando/parcial/fechado) continua sendo o do G2, só pelos imports — patrimônio, triagem e diagnóstico **não** mudam o "fechado" (o lembrete do G5 depende disso)
- [ ] clicar numa célula que falta leva ao lugar de fazer: extrato/fatura/salário → aba Importar com o tipo; triagem → aba Lançamentos filtrada em Não Identificado naquele mês; patrimônio e diagnóstico só mostram o texto (são feitos pelo Telegram e pela rotina do assistente)
- [ ] a API devolve o que a grade precisa numa chamada só (o `GET /api/fechamento` ganha, por mês, `patrimonio: [{conta, pessoa, tem_print}]` e `diagnostico: bool`; somas e contagens em SQL; a regra das células é pura e testada)
- [ ] testes cobrem os quatro estados de cada tipo de linha, o mês corrente, o "não se aplica" antes do primeiro print e o clique da triagem

## Exemplo

Mês selecionado outubro/2026, valores inventados: Itaú extrato — set feito, out parcial; Itaú fatura — set feito, out falta; Salário — set parcial (estimado); Print C6/Paola — set não se aplica (antes do primeiro print), out feito; Triagem — set parcial "26", out parcial "2"; Diagnóstico — ago feito, set falta, out não se aplica.
